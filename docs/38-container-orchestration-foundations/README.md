# Container Orchestration Foundations

Container orchestration is the practice of running, replacing, scaling, and connecting containers as a coordinated system instead of starting each container by hand.

This section is beginner-friendly and conceptual. It does not require a real cluster, cloud account, or provider-specific deployment.

## Start Here

1. [Orchestration Basics](orchestration-basics.md)
2. [Desired State, Scaling, And Self-Healing](desired-state-scaling-self-healing.md)

## What You Should Learn

- Why a single container is not the same as an operated application
- How an orchestrator decides where containers should run
- Why desired state is central to Kubernetes
- How scaling and self-healing work at a high level
- Why the examples in this repository are local-only learning material

## Local-Only Learning Boundary

The examples in this stage are meant for reading, review, and optional local experimentation. They are not production-ready deployment templates and they do not create real cloud infrastructure.
