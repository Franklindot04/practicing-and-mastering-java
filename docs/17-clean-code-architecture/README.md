# Clean Code, SOLID, And Basic Architecture

Professional Java is not only about syntax. It is about writing code that can be understood, tested, changed, and trusted.

Key topics:

- Clear names
- Small methods
- Single Responsibility Principle
- Open/Closed Principle
- Liskov Substitution Principle
- Interface Segregation Principle
- Dependency Inversion Principle
- Layered architecture basics

Common mistakes:

- Making classes responsible for too many things.
- Hiding dependencies inside methods.
- Overengineering tiny programs.
- Skipping tests around important behavior.

Practice prompts:

- Refactor a long method.
- Split input, business logic, and output into separate classes.
- Add tests before refactoring.

Before moving on, you should be able to explain why maintainable code is a feature.
