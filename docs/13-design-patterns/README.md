# Design Patterns

Design patterns are reusable solutions to common design problems. They are vocabulary, not rules to force into every program.

Useful patterns to learn:

- Strategy
- Factory Method
- Builder
- Adapter
- Observer
- Repository

Common mistakes:

- Adding patterns before there is a real design problem.
- Hiding simple logic behind too many abstractions.
- Memorizing diagrams without understanding tradeoffs.

Practice prompts:

- Use Strategy for payment methods.
- Use Builder for a configuration object.
- Use Adapter to wrap an incompatible API.

Before moving on, you should know the problem each pattern solves and when it would be too much.
