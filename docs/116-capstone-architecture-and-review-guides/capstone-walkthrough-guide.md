# Capstone Walkthrough Guide

Use this flow for interviews, portfolio reviews, or self-assessment.

1. Start with the problem statement and scope.
2. Draw the main boundaries and data ownership.
3. Explain one success path and two failure paths.
4. Show the tests that prove local behavior.
5. Discuss observability, runbooks, and recovery.
6. Name limitations and what real deployment would require.
7. Connect the capstone back to earlier repository stages.

## Comparison With Earlier Projects

Earlier projects isolate specific skills. The capstones combine those skills and ask for trade-off reasoning: consistency versus availability, retries versus duplication, local test evidence versus operational evidence, and simulation clarity versus real infrastructure complexity.
