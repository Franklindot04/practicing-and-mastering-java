# Capstone Requirements and Scope Review

Review each capstone by asking what problem it claims to solve, which capabilities are implemented, which capabilities are simulated, and which claims would require deployment or operational evidence.

## Checklist

- Requirements are explicit and traceable to code, tests, or docs.
- Scope boundaries are visible: included capabilities, excluded capabilities, and future improvements are separate.
- Simulations are named honestly and are not presented as durable systems.
- Earlier repository topics are integrated rather than copied without context.
- Remaining gaps are documented without turning them into hidden claims.

## Review Questions

1. Which requirement is most central to the capstone objective?
2. Which requirement is hardest to prove with local tests?
3. Which feature would be risky to present without limitations?
4. Which future improvement would add the most learning value?
